Note A - Source loss.  Both loss terms use the COMBINED prediction, as in your plan:
      y_comb = theta_S * y_S + theta_T * y_T
      L = MSE( y_comb(X_S), Y_S )  +  MSE( y_comb(X_T), Y_T )  +  lambda_p * MMD
  This was already what the GitHub version did, so no change was needed. Please be
  aware that it is a deliberate deviation from the paper: Eq. 18 there trains the
  source term on the source head y_S alone (Eq. 17) and only the target term on the
  combined output (Eq. 16). (Eq. 13 in the paper is the input tensor, not the loss.)
  Effect of the choice: theta_S and theta_T now receive gradients from source AND
  target batches, and the target head G_Y^T is also pulled by the source labels.

Note B - LR schedule.  Cosine annealing is kept and is ON by default, but it now
  stops at a floor of  lr * 0.2  (5.0e-4 -> 1.0e-4) instead of decaying to 0, so the
  last epochs are still trained properly. Verified: LR goes 5.0e-4 -> 1.0e-4 and
  stays there. New flags: --lr-min-ratio (default 0.2) and --no-scheduler (fixed LR,
  the paper's setting). The old --use-scheduler flag was removed (the GitHub
  version had switched the scheduler OFF by default, with no floor).

Note C - Optimizer.  Paper Section 4.1 states that the model is optimized with
  AdamW. The plan claimed plain Adam. GitHub had changed AdamW to Adam; it is
  AdamW(lr=5e-4, weight_decay=1e-4) again. (The paper does not give a weight-decay
  value; 1e-4 is your existing setting.)

Note D - Validation.  Validation RMSE picks the best epoch, computed on the combined
  prediction over the held-out 10 % source cells (as in your plan). The paper only
  says "model selected based on the lowest RMSE on the validation set"; it does not
  name which predictor output is used, so this choice cannot be checked against it.

Note E - MAPE.  The plan claimed the paper uses standard per-sample MAPE. Paper
  Eq. 23 divides by y, defined right below it as the CYCLE LIFE, not by the
  per-sample RUL:
      MAPE = (1/n) * sum_i |y_i - y_hat_i| / y * 100
  The GitHub version had made strict per-sample MAPE the primary metric. The primary
  metric ("test_mape") is now the paper's definition, computed against each cell's
  own cycle life (see Section 8). Per-sample, floor and raw MAPE stay as
  auxiliary numbers. Sanity check on the paper's own numbers: RMSE 153 cycles on
  cells averaging ~1,900 cycles of life is ~8 %, consistent with MAPE 7.3 %, while
  per-sample MAPE on RUL windows near end of life would be far larger.

Note F - num_runs.  The plan's "defaults" section lists num_runs = 10 (paper
  Section 4.1: ten repetitions, predictions averaged). It is now the default, in
  both run_benchmark() and the CLI. CONSEQUENCE: a plain run trains 10 models and
  writes checkpoints/<name>_run1.pt ... _run10.pt (no single <name>.pt). For a quick
  single run pass  --num-runs 1  (this writes the checkpoint path exactly as given).


1. PROBLEM FORMULATION
--------------------------------------------------------------------------------
Predict the Remaining Useful Life (RUL) of a lithium-ion cell at ANY point in its
life from the most recent ~30 cycles of voltage, current and capacity:
      RUL = N_life - N_age                                          (paper Eq. 11)

Both datasets in the paper are LFP/graphite A123 APR18650M1A cells (1.1 Ah), so
the domain shift is in operating protocol, not chemistry:
  - Source, TRI / MATR (Severson et al.): 124 cells (169 in the BatteryLife copy,
    which adds Attia batch 4), VARIED fast-charging, identical discharge.
    Cycle life ~150 - 2,300.
  - Target, LHP / HUST: 77 cells, VARIED multi-stage discharge, identical
    fast-charging. Cycle life 1,100 - 2,700 (mean 1,898).
A model trained only on the source degrades badly on the target. HybridoNet-Adapt:
  a) extracts temporal features z (128-D) with LSTM -> attention -> NODE;
  b) aligns source and target features with Maximum Mean Discrepancy (MMD);
  c) keeps two regression heads (G_Y^S, G_Y^T) blended by trainable weights
     theta_S, theta_T.
Note: the target cells used for adaptation are LABELED here (Eq. 18 has a target
MSE term), even though the abstract loosely says "unlabeled target".


2. DATA PREPROCESSING & 18-D FEATURE EXTRACTION
--------------------------------------------------------------------------------
Script: preprocess_hybrido.py
Input : per-cell parquet files with voltage_V, current_A, capacity_Ah, cycle_number.

Step 2.1  Per-cycle features.
  Each signal (voltage, current, capacity) is median-filtered (kernel 3) to remove
  spikes, then summarized by 6 statistics:
      Mean, Std, Min, Max, Variance, Median
  -> 3 signals x 6 statistics = 18 numbers per cycle.

Step 2.2  Rolling windows.
  A window covers 30 consecutive cycles. From it, 10 cycles are picked uniformly
  (one every three cycles), giving a sample of shape (10, 3, 6), later flattened
  to (10, 18) for the LSTM. Windows slide along the cell's whole life:
      --window-size 30 (default)
      --stride 10 (default; overlapping windows, more training samples)
      --stride 30 gives the paper's non-overlapping windows.

Step 2.3  Labels.
  For a window ending at cycle C_end:  RUL = EOL - C_end.
  EOL is the first cycle where capacity drops below 80 % of nominal.
  Windows stop once C_end reaches EOL.

Output: one .npz per dataset with X, Y (RUL), sample_ids, cell_ids. A single run
converts every dataset it finds and also writes TRI/MATR and LHP/HUST aliases.


3. DISJOINT CELL-LEVEL PARTITIONING (ZERO-LEAKAGE GUARANTEE)
--------------------------------------------------------------------------------
Function: train_hybrido.py -> split_by_cell_id()

Windows from the same physical cell are highly correlated, so splits are made by
CELL, never by window:
  - Source (MATR):
      90 % of cells -> source training set
      10 % of cells -> validation set (checkpoint selection)
  - Target (HUST):
      60 % of cells -> target adaptation set (LABELED; used in the target MSE loss
                       and in MMD)
      40 % of cells -> blind test set (used once, at the very end)
The test set contains only unseen cells. Splits use a fixed seed (42).


4. FEATURE & RUL NORMALIZATION
--------------------------------------------------------------------------------
Step 4.1  Features.  A MinMaxScaler is fitted on the source-training windows plus the
  target-adaptation windows (over all samples and time steps, per each of the 18
  features), then applied to validation and blind-test windows. Values are clipped
  to [-0.5, 1.5] as a safety net. The blind test set never influences the scaler.

Step 4.2  RUL.  Labels are scaled into [0, 1] by a fixed physical ceiling
  (default 2500 cycles):  y_scaled = RUL / ceiling;  RUL_pred = y_pred * ceiling.
  This keeps targets away from the saturated ends of the final Sigmoid.
  See Section 10 for a known problem when target RUL exceeds the ceiling.


5. NEURAL ARCHITECTURE                                   (file: model_hybrido.py)
--------------------------------------------------------------------------------
Input x: (Batch, 10, 18)

5.1  Two-layer LSTM (hidden 128, dropout 0.1) -> H_lstm (Batch, 10, 128).
5.2  Multi-head self-attention (4 heads, embed 128), with a residual connection and
     LayerNorm -> H_attn (Batch, 10, 128).
5.3  The LAST time step is selected: h = H_attn[:, -1, :]  (Batch, 128).
5.4  Neural ODE block: dz/dt = W*z + b (one linear layer), integrated with RK4 over
     t in [0, 1] using 2 steps. It models continuous-time ageing dynamics.
5.5  LayerNorm(128) after the ODE -> latent z (Batch, 128).
5.6  Two identical predictor heads, G_Y^S (source) and G_Y^T (target), exactly the
     paper's Table 2:
         Linear(128->64) -> ReLU -> BatchNorm1d(64) -> Dropout(0.1) ->
         Linear(64->32)  -> ReLU -> BatchNorm1d(32) -> Dropout(0.1) ->
         Linear(32->1)   -> Sigmoid
     (BatchNorm is the default; --norm-type layernorm is still available.)
5.7  Trade-off weights.  Target prediction (paper Eq. 16):
         Y_hat_T = theta_S * G_Y^S(z) + theta_T * G_Y^T(z)
     theta_S, theta_T = softmax(theta_logits), logits start at [0, 0], so both
     start at 0.5 and always sum to 1 (kept as-is by your decision; the paper uses
     two free scalars initialised at 0.5).


6. DOMAIN ADAPTATION VIA MMD                                 (file: mmd_loss.py)
--------------------------------------------------------------------------------
MMD measures the distance between the source feature distribution and the target
feature distribution:
      MMD^2 = E[k(zs,zs')] - 2 E[k(zs,zt)] + E[k(zt,zt')]
The implementation uses 5 Gaussian kernels with geometrically spaced bandwidths
(centered on an adaptive bandwidth) and a scale normalization for stability. The
paper (Eq. 19) describes a single Gaussian kernel; see Section 9.

Dynamic weight (paper Eq. 21):
      lambda_p = 2 / (1 + exp(-10 * epoch/epochs)) - 1
It grows from about 0.17 at epoch 1 of 30 to about 1.0 at the end, so alignment is
gentle early on and strong late. The loss term is  lambda_p * MMD  with NO extra
multiplier (mmd_weight defaults to 1.0; an earlier 0.1 multiplier was removed).


7. TRAINING LOOP (AS IMPLEMENTED NOW)                (train_hybrido_session)
--------------------------------------------------------------------------------
7.1  Optimizer: AdamW, lr 0.0005, weight_decay 1e-4, gradient-norm clipping 5.0.

7.2  LR schedule: CosineAnnealingLR with T_max = number of epochs and
     eta_min = lr * lr_min_ratio (default 0.2):
         lr_t = 1e-4 + (5e-4 - 1e-4) * (1 + cos(pi * t / T)) / 2
     It steps once per epoch and never reaches zero. The LR printed in the epoch
     log is the value AFTER that epoch's step. If early stopping ends training
     before the last epoch, the floor is simply not reached.
     --no-scheduler gives a constant 0.0005 (the paper's fixed LR).

7.3  Each step takes one source batch and one target batch:
       source term : MSE( theta_S*G_Y^S(z_S) + theta_T*G_Y^T(z_S), Y_S )   (combined)
       target term : MSE( theta_S*G_Y^S(z_T) + theta_T*G_Y^T(z_T), Y_T )   (combined)
       MMD term    : lambda_p * MMD(z_S, z_T)
       total loss  = source + target + MMD term
     Both terms use the combined prediction (see Note A: the paper's Eq. 18 uses the
     source head alone for the source term). Gradients: the feature extractor, both
     heads and the theta logits are all trained by both terms.

7.4  Validation after every epoch: combined prediction on the held-out source cells;
     RMSE in cycles. The epoch with the lowest validation RMSE is kept.

7.5  Schedule: up to 30 epochs; training stops early if validation RMSE has not
     improved for 8 consecutive epochs (--early-stop-patience 0 disables it).

7.6  Final evaluation: the best checkpoint is loaded and the blind target test cells
     are scored exactly once with the combined prediction.

7.7  Repetitions (default 10, seeds 42..51): each run is trained and tested
     independently; the final prediction is the average of the runs' test
     predictions (paper Section 4.1). Checkpoints are saved as <name>_run1.pt ...
     <name>_run10.pt. With --num-runs 1 the checkpoint is written exactly to
     --checkpoint-path.


8. EVALUATION METRICS
--------------------------------------------------------------------------------
Reported on the blind target test cells:

1. RMSE (cycles):  sqrt( mean( (y - y_hat)^2 ) )
2. R2:             1 - sum((y - y_hat)^2) / sum((y - mean(y))^2)
3. MAPE, paper definition (Eq. 23)          <- PRIMARY, result key "test_mape"
       MAPE = mean_i( |y_i - y_hat_i| / N_life(cell of i) ) * 100 %
   y_i, y_hat_i are the true and predicted RUL of window i; N_life is the TOTAL
   cycle life of the cell that window i belongs to. Because N_life is far larger
   than the RUL, the metric stays bounded near end of life.
   The .npz files store RUL only, so N_life is recovered per cell:
       N_life(cell) = max(RUL over that cell's windows) + window size (30)
   because RUL = N_life - current_cycle and a cell's first window ends at cycle 30.
   This was verified to be exact on synthetic cells (true lives 300 / 517 / 421 were
   recovered exactly through the real preprocessing code). If you preprocess with
   a different --window-size the estimate is off by that difference (a few cycles).
4. Per-sample MAPE (auxiliary):  mean( |y - y_hat| / max(y, 1) ) * 100 %
   Explodes near end of life; shown only for comparison.
5. Floor MAPE (auxiliary): per-sample MAPE restricted to windows with RUL >= 50.
6. Raw scikit-learn MAPE (auxiliary): unbounded near end of life.


9. DELIBERATE DEVIATIONS FROM THE PAPER
--------------------------------------------------------------------------------
Chosen by you or by earlier project decisions; listed so they can be stated openly.
  - Source loss: combined prediction y_comb (your plan) vs the paper's Eq. 18,
    which uses the source head y_S alone for the source term.
  - theta parameterisation: softmax (sums to 1) vs the paper's free scalars.
  - Learning rate: cosine decay to a floor vs the paper's fixed 0.0005.
  - Epochs: up to 30 with early stopping (patience 8) vs the paper's 10 epochs.
  - MMD kernel: 5 Gaussian kernels with adaptive bandwidth vs a single Gaussian.
  - Weight decay 1e-4 (the paper says AdamW but gives no value).
  - Validation head: combined prediction on source validation cells (paper silent).
  - Data splits: the paper uses the TRI training subset (41 cells) as source and
    subsets of the LHP cells as targets. This project splits all MATR cells 90/10
    and all HUST cells 60/40 by cell. Absolute numbers should therefore not be
    expected to match the paper's table exactly. Use --severson-only for the
    124-cell version of MATR.
  - The feature scaler is fitted on source-train + target-adaptation windows.


10. KNOWN LIMITATIONS (NOT CHANGED IN THIS REVISION)
--------------------------------------------------------------------------------
  - RUL scaler ceiling.  If a target RUL exceeds the source's ceiling, RobustRULScaler
    expands its ceiling part-way through setup, so source labels and target labels
    end up scaled differently. MATR -> HUST does not trigger this. Warning sign in
    the log: "Auto-expanded physical RUL ceiling". If you see it, rerun with
    --rul-ceiling set above the largest RUL in BOTH datasets, and pass the same
    value to visualize_model.py and investigate_model.py.
  - Checkpoint selection uses source-domain validation cells only, so the chosen
    epoch is not necessarily the best one for the target.
  - test_hybrido.py writes checkpoints/hybrido_best.pt in the current directory.
    Run the tests BEFORE training, not after.
  - src/hybridonet-adapt/download_datasets.py extracts .pkl files that the
    preprocessor cannot read. Use src/downloads/download_batterylife_data.py.
  - The data download itself has not been tested end to end (Zenodo was not
    reachable from the test environment).


11. COMPLETE RUN GUIDE, FROM A CLEAN MACHINE
--------------------------------------------------------------------------------
Run every command from the repository root. Bash on Linux, macOS, WSL or Colab.

Step 0: get the code and set up Python
    git clone https://github.com/divyansh070/ashwini_prof_project.git
    cd ashwini_prof_project
    python3 -m venv .venv
    source .venv/bin/activate
    pip install torch numpy pandas pyarrow scipy scikit-learn matplotlib

Step 1: verify the code (do this BEFORE training)
    python src/hybridonet-adapt/test_hybrido.py
    (expected: ALL 8/8 HARDENED TESTS PASSED SUCCESSFULLY)

    python src/downloads/download_batterylife_data.py --skip CALCE SNL RWTH Stanford
    ls data/real_processed/matr | wc -l      # roughly 169
    ls data/real_processed/hust | wc -l      # roughly 77

    python src/hybridonet-adapt/preprocess_hybrido.py
    (paper's non-overlapping windows: add  --window-size 30 --stride 30)

Step 4: train
  Quick single run (recommended first):
    python src/hybridonet-adapt/train_hybrido.py \
      --source data/hybridonet/processed/MATR_raw_features.npz \
      --target data/hybridonet/processed/HUST_raw_features.npz \
      --epochs 30 --early-stop-patience 8 --batch-size 128 --lr 0.0005 \
      --norm-type batchnorm --num-runs 1 \
      --checkpoint-path checkpoints/hybrido_best.pt

  Full paper benchmark (10 runs, ensemble averaging; this is now the default):
    python src/hybridonet-adapt/train_hybrido.py \
      --source data/hybridonet/processed/MATR_raw_features.npz \
